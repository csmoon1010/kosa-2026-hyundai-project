# RAG 패턴 후보 선정 및 최종 RAGAS 평가 작업 계획서

## 1. 목적과 평가 기준

`mini_project_final.ipynb`에 저장된 Pre-retrieval 실행 142, Retrieval 실행 145, Post-retrieval 실행 148을 근거로 후보를 좁힌 뒤, 동일한 생성 조건의 RAGAS 평가로 최종 파이프라인을 선택한다. 현재 결과는 후보 선정 근거이며 최종 선택 결과는 아니다.

평가 데이터는 현재 골든셋 22문항(답변가능 19, 무답변 3)을 사용한다. 기존 RAGAS 요약은 비교 참고 자료로만 사용하고, 기본 벡터 검색(K=6)을 BASE로 확정하고 공통 기준선 22문항만 먼저 평가한다. 이 단계에서 나머지 후보는 수행하지 않는다. 패턴 평가의 간단한 생성 프롬프트와 기존 RAGAS의 업무·인용 프롬프트가 다르므로 기존 점수를 그대로 합치거나 개선률을 계산하지 않는다.

최종 선택은 **평가 유효성 → 일반 메트릭 → 커스텀 메트릭 → 경제성 → 최종 전체 확인** 순서로 판단한다. 질문 유형별 선택 적용을 허용하며, 비용·지연·평가 예산에 별도 상한을 두지 않고 품질과 비용의 비교 결과를 제시한다. 검색 순위나 오기권만으로 기법을 확정하지 않는다. 이번 22문항은 후보 탐색에 이미 사용됐으므로 최종 결과는 해당 데이터에 대한 검증으로 표시하고, 선택 적용할 유형은 유형별 신규 골든셋 5문항씩으로 확인한다. 작은 검증셋으로 운영 전반의 성능을 확정하지 않는다.

## 2. 최신 결과에 따른 후보 선정

| 단계 | 우선 평가 후보 | 최신 결과와 선정 이유 | 제한 사항 |
|---|---|---|---|
| 기준선 | 기본 벡터 검색, K=6 | hit 0.947, recall 0.801; 낮은 비용과 범용 성능 | 조건 질문 근거·답변 누락이 남음 |

| Retrieval | parent_doc | 조건 hit·mrr 1.0, 오기권 0%; 전체 오기권 5.3% | 전체 hit 0.895, recall 0.711; 집계·부정/예외 근거 손실 |
| Post | rerank_llm | recall 0.819, mrr 0.860, ndcg 0.788; 오기권 5.3% | USD 0.125144로 기본 0.043770의 약 2.9배 |
| Post | mmr_wide_0.9 | 기본과 hit·recall 동일, 오기권 5.3%, USD 0.039903 | 지연 1.357초로 기본 1.286초보다 약 6% 높음; 순위 개선은 작음 |

다음 기법은 1차 필수 평가에서 제외하고, 우선 후보가 문제를 해결하지 못할 때만 추가한다.

- HyDE: 조건·집계의 대안. 조건 근거 확보가 좋지만 부정/예외·시점/기한 hit가 0.5이므로 범용 후보에서 제외한다.
- Step-back: 단일홉·시점/기한의 대안. 쿼리 확장은 조건 근거 확보의 대안이나 조건 오기권 50%가 남는다.
- Hybrid Dense 0.7: 부정/예외 근거 확보의 대안. Hybrid 0.5·Ensemble은 단일홉 순위 개선 대안이다.
- MMR 0.7: 단일홉에서 품질 대비 비용·지연 절감 효과를 비교할 대안이다.
- 재작성·질의 분해·메타데이터 라우팅·Cross-Encoder·임베딩 필터·LLM 문맥 추출: 현재 전체 성능·비용 또는 근거 보존 결과로 우선순위를 낮춘다.
- Auto-merging: Parent와 검색 지표가 같고 오기권이 더 높아 우선 제외한다.
- Sentence-window: recall 1.149 및 유형별 nDCG 1 초과는 중복 창과 기본 DB 분모 차이가 개입된 결과다. 근거 중복 집계·분모 정합성 확인 전에는 성능 우위로 선정하지 않는다.

## 3. 후보 선정 로직과 비교 구성

### 3.1 BASE 공통 기준선 확정

기본 벡터 검색 K=6을 **BASE**로 확정한다. 검색기를 다시 선정하기 위한 5개 구성의 전체 RAGAS 비교는 수행하지 않는다. 기존 22문항의 검색·생성 답변을 한 번 준비하고 여섯 지표를 해당 기법의 한 셀에서 평가해 공통 기준선을 확보한다.

### 3.2 유형을 한정한 후보 평가

후보 평가는 자동 실행하지 않는다. 적용 검토가 필요한 경우에만 기법과 질문 유형을 명시해 등록하고, 해당 유형의 기존 문항만 BASE의 동일 문항 결과와 비교한다. BASE 결과는 재사용한다.

| ID | 구성 | 평가 범위 | 실행 조건 |
|---|---|---|---|
| BASE | 기본 벡터 검색 K=6 | 기존 22문항 전체 | 먼저 수행할 공통 기준선 |
| P1 | structured_query → 기본 검색 | 조건 2문항 | 조건 선택 적용 검토 시 명시적으로 등록 |
| R1 | parent_doc | 조건 2문항 | 조건 선택 적용 검토 시 명시적으로 등록 |
| S1 | 후보 12개 → LLM 리랭킹 → K=6 | 집계 3·부정/예외 2·시점/기한 2 중 적용할 유형 | 해당 유형을 명시적으로 등록 |
| S2 | MMR lambda=0.9, fetch_k=36 | 적용 검토 대상 유형만 | 품질 대비 비용 비교가 필요할 때만 등록 |

후보의 메트릭 하락·업무 위험 상승을 진단한 뒤 문항·검색 근거·품질·비용을 직접 확인해 유형별 검증 경로를 지정한다. 전 유형에 대한 후보 자동 순회, 조합 자동 탐색 및 3회 반복을 제거한다.

### 3.3 신규 유형 검증 및 최종 라우팅

직접 선정한 유형만 신규 5문항을 생성·검수해 별도 JSON에 저장하고 BASE와 선정 후보를 각각 한 번 평가한다. 기존 문항과 신규 문항의 결과는 분리한다. 신규 검증을 확인해 직접 승인한 유형에만 해당 기법을 선택 적용하고 나머지는 BASE를 유지한다.

실제 라우터는 원질문만 입력받으며 골든 유형·정답·answerable을 받지 않는다. 유형 경로를 고정한 후 기존 22문항 전체에서 실제 라우팅 정책을 한 번 평가해 다른 유형의 오분류·성능 저하 및 무답변 대응을 확인한다. 신뢰도 0.8 미만 또는 처리 오류는 BASE로 복귀하고 라우팅 비용도 포함한다. 선택 적용 경로가 없으면 기존 BASE 결과를 재사용하고 최종 모델 재호출을 생략한다.

## 4. 평가 구현 및 실행 절차

### 4.1 공통 평가 조건 고정

- DB·문서·골든셋의 해시, 청킹 설정, 후보 구성, 모델명과 실제 응답 모델 버전, 프롬프트를 노트북 내부에서 관리하고 공통 조건을 마크다운 셀에 요약한다.
- 생성 모델은 LOWER, 심사 모델은 JUDGE, 임베딩은 현재 EMBEDDING을 유지한다. 기존 RAGAS의 업무·표 행 조건·인용 프롬프트를 모든 후보에 동일하게 적용한다.
- 최종 반환 K=6을 기본으로 한다. Parent의 문맥 길이 차이, S1의 WIDE=12, S2의 fetch_k=36·lambda=0.9는 구성 정보에 명시한다.
- 검색·생성 준비와 지표 계산은 함수로 분리하되, BASE·각 후보 기법은 각각 별도 평가 셀에서 답변 준비와 여섯 지표 계산을 모두 완료한다. 현재 작업의 구성·데이터셋·유형을 명시하고, 후보는 요청한 시점에만 생성해 BASE 단계의 보조 인덱스 비용을 없앤다. 골든 유형·정답·answerable은 생성·검색·라우팅 입력에서 제외한다.
- 문항별 최종 검색 본문·순서·출처, 변환 질의, 선택 경로, 실제 답변은 노트북 메모리에서 관리한다. 상세 출력은 핵심 실패 문항만 제시한다. 인용 번호는 최종 반환 문맥의 순서로 붙인다.
- 검색·생성 지연과 토큰 비용, 라우팅·질의 변환·후처리 비용을 기록한다. RAGAS 심사 비용 및 인덱스 구축 비용은 운영 질의 비용과 분리한다. 기존 PRICES 기준 추정임을 명시한다.

### 4.2 RAGAS 및 커스텀 평가

| 지표 | 대상 | 선택에서의 역할 |
|---|---|---|
| Faithfulness | 기존 답변가능 19 + 선정 유형의 신규 답변가능 문항 | 생성 주장이 검색 근거로 뒷받침되는지 확인 |
| ResponseRelevancy | 기존 답변가능 19 + 선정 유형의 신규 답변가능 문항 | 질문 요구사항에 대한 답변 관련성; 짧은 금액·표 답변은 원문도 확인 |
| LLMContextPrecisionWithReference | 기존 답변가능 19 + 선정 유형의 신규 답변가능 문항 | 실제 정답에 유용한 근거의 순위·비중 확인 |
| LLMContextRecall | 기존 답변가능 19 + 선정 유형의 신규 답변가능 문항 | 정답에 필요한 정보가 실제 문맥에 포함되는지 확인 |
| CitationFormat | 기존 답변가능 19 + 선정 유형의 신규 답변가능 문항 | 인용 번호 존재·유효 범위 확인; 인용 내용의 정확성은 별도 검토 |
| BusinessSafetyScore | 기존 22 + 선정 유형의 신규 문항 | 평균과 함께 위험 수준 2·3의 문항 수 및 판정 사유 확인 |
| 오기권·무답변 대응 | 기존 답변가능 19·무답변 3 + 해당 신규 문항 | 부당한 정보 부족 응답과 없는 정보 생성 여부를 구분 |
| 필수 항목 완전성 | 조건·예외·집계 등 | 제출자료·균주·금액·기간·표 행 조건 누락을 문항별 체크리스트로 확인 |

검색 hit·recall·mrr·ndcg도 진단값으로 기록하지만 서로 다른 반환 단위의 점수를 직접 종합하지 않는다. 문맥 품질은 실제 반환 문맥에 대한 RAGAS 결과와 필수 근거 검토로 확인한다. 필수 항목 체크리스트는 기존 참조 정답과 원문에서 작성하고 답변 생성에는 제공하지 않는다.

기존 오기권 검사는 `문서에 없음` 문자열에 의존하므로 RAGAS 프롬프트의 `제공된 문서에서 정보를 찾을 수 없습니다.`와 같은 응답도 잡도록 판정 규칙을 통일한다. 부분 답변과 전면 기권은 메모리에서 구분하고 요약 결과에 반영한다.

### 4.3 추가 골든셋 생성·검수

BASE 기준선을 확보하고 명시적으로 등록한 후보를 해당 유형의 기존 문항에서 비교한 뒤, **특정 유형에 기본 검색과 다른 기법을 선택 적용할 후보가 나온 경우에만 해당 유형의 신규 5문항**을 생성·검수한다. 기본 검색을 유지하는 유형은 신규 골든셋을 만들지 않는다. 추가 대상 유형 수를 T라 하면 신규 문항 수는 5×T이며, 전체 추가 문항 수나 파일 수를 미리 고정하지 않는다. 예를 들어 조건·부정/예외 2개 유형만 선택 적용을 검토하면 신규 10문항과 JSON 2개를 만든다.

추가 대상 선정은 일반·커스텀 메트릭상 개선 가능성, 유형별 적용 사유, 비교할 후보를 근거로 결정하고 마크다운 셀에 짧게 기록한다. 현재 조건의 구조화 질의/Parent 및 집계·부정/예외·시점/기한의 LLM 리랭킹은 검토 대상이며 자동으로 추가 생성할 유형은 아니다. 검수 탈락에 대비해 초안을 여유 있게 생성하되 최종 JSON에는 대상 유형당 통과 문항 5개만 담는다.

1. **초안 생성**: 실제 문서의 필수 자료·조건·예외·기간·금액에서 질문, 유형, 참조 정답, 출처·페이지·직접 인용, 필수 답변 항목을 구성한다. 기존 22문항의 단순 바꿔쓰기와 동일 사실 조합의 중복은 제외한다.
2. **1차 인용정합성**: 기존 로직처럼 공백을 정규화한 8자 이상 직접 인용이 지정 근거에 실제 존재하는지 검사한다. 멀티홉은 각 출처와 인용의 연결을 확인하고, 표는 행·열 조건도 확인한다.
3. **1.5차 정답실질성**: 정답이 빈칸·공란·N/A 등 형식적 내용이 아닌 실제 업무 정보를 포함하는지 확인한다. 정답의 조건·필수 자료·예외가 인용으로 뒷받침되는지도 검토한다.
4. **2차 자기완결성**: 질문만 읽어 업무 대상·요구 정보·범위를 특정할 수 있어야 한다. “위 표”, “내용2”, 항목 번호·페이지 위치에 의존하는 질문은 제외한다. 기존 자기완결성 심사 기준을 재사용한다.
5. **최종 선정·고정**: 답변가능 유형은 세 검수를 모두 통과하고 유형·중복 기준을 충족한 신규 5문항씩 선정한다. 무답변 유형은 아래 별도 검수 기준을 적용한다. 유형별 통과 문항이 5개 미만이면 해당 유형을 보완 생성하고 같은 검수를 반복한다. 검수 단계별 통과·탈락 수와 대표 사유를 간결한 마크다운 표로 정리한다.

무답변 유형에 별도 기법을 선택 적용할 후보가 있을 때만 신규 5문항을 만들며, 문항은 문서 범위에서 실제로 답을 찾을 수 없는 질문으로 구성한다. 답변가능 문항의 인용정합성·정답실질성 검사를 그대로 적용하면 정상적인 무답변 문항이 탈락하므로, 1차는 전체 문서 검색과 원문 검토로 답의 부재를 확인하고 검색·검토 근거를 남긴다. 1.5차는 표의 빈 셀을 묻는 질문이나 단순 파싱 누락을 제외하고 적절한 정보 부족 안내가 참조 정답인지 확인한다. 2차 자기완결성은 동일하게 적용한다. 무답변은 일반 메트릭·CitationFormat 평가에서 제외하고 BusinessSafetyScore와 무답변 대응으로 평가한다. 후보와 라우팅 규칙을 기존 22문항으로 고정한 뒤 추가 검증 문항을 생성·확정하고, 후보 성능을 보고 문항을 교체하지 않는다. 추가 문항에서 실패해 경로를 수정하면 해당 셋은 이후 개발 검증셋으로 표시하고 독립 검증으로 주장하지 않는다.

신규 골든셋은 선정된 유형에 한해 `golden_validation/` 아래 유형별 새 JSON 파일로 저장한다. 기존 `golden_dataset.json`은 유지하고 기존 문항을 신규 JSON에 중복 저장하지 않는다.

아래는 유형별 파일명 규칙이며, 선정되지 않은 유형의 파일은 생성하지 않는다.

| 선택 적용 검증 대상 유형 | 선정 시 신규 문항 수 | JSON 경로 |
|---|---:|---|
| 단일홉 | 5 | `golden_validation/single_hop.json` |
| 멀티홉 | 5 | `golden_validation/multi_hop.json` |
| 표 | 5 | `golden_validation/table.json` |
| 집계 | 5 | `golden_validation/aggregation.json` |
| 조건 | 5 | `golden_validation/condition.json` |

각 JSON은 기존 골든셋의 필드 형식과 호환되도록 질문·유형·answerable·참조 정답·출처/페이지·직접 인용을 포함하고, 고유 ID·신규 문항 표시·필수 답변 항목·검수 단계별 결과를 함께 기록한다. 무답변은 직접 인용을 지어내지 않고 답의 부재 확인 근거를 기록한다. 확정된 파일의 해시를 기록하고 모든 비교 후보에서 동일하게 재사용한다.

선정된 유형의 평가 시 기존 `golden_dataset.json`의 동일 유형 문항과 해당 신규 JSON의 5문항을 불러온다. 기존/신규 구분을 유지한 채 같은 후보들을 비교하고, 기존 성능 유지와 새 사례의 개선을 별도 집계한다. 문항 목록을 마크다운에 중복 나열하지 않고 유형별 개수·파일 경로·검수 요약을 남긴다. 생성·검수 비용은 질의 처리 및 RAGAS 심사 비용과 분리해 집계한다.

### 4.4 기법별 셀 분리 및 결과 확인

- **BASE 셀**: 기존 22문항의 검색·생성 답변과 일반 4지표·커스텀 2지표를 같은 셀에서 모두 계산해 공통 기준선을 확보한다.
- **후보 기법별 셀**: P1·R1·S1·S2는 각각 별도 셀로 나눈다. 명시적으로 선택한 기법만 적용하려는 유형의 기존 문항에서 평가하고, 해당 셀에서 전체 지표를 계산한 뒤 BASE와의 결과를 바로 표시한다. 기본 설정은 후보 선택 목록을 비워 BASE만 수행한다.
- 기법 안에서는 일반 4지표를 한 `evaluate()`로 함께 계산하고, 인용 형식과 업무 안전성을 각 평가 대상에 맞게 이어서 계산한다. 세 `evaluate()` 호출은 같은 기법 셀 안에 있으며 지표별 셀로 나누지 않는다.
- 같은 커널 세션에서 완료한 결과와 생성 답변은 메모리에서 재사용한다. 중단·오류 발생 시 해당 기법 셀을 다시 실행하면 완료 결과를 재사용하고 미완료 평가를 진행한다. 커널 재시작 시 메모리 결과는 사라진다.
- 신규 검증은 공통 함수 `final_run_validation_base(index)`와 `final_run_validation_candidate(index)`를 index별 별도 셀에서 호출한다. index는 0부터 시작하며 `final_provisional_policy`의 유형·후보 순서를 따른다. 현재 0=조건/P1, 1=조건/R1, 2=부정/예외/S1이다. BASE와 후보의 결과는 각 호출 셀에 보존하며 동일 유형의 신규 5문항과 완료된 BASE 결과를 재사용한다. 각 기법의 전체 지표는 함께 계산한다. 대상이 늘면 호출 셀을 복사하고 index만 바꾼다. 모든 대상 평가 후 7-8 진단으로 진행한다.
- 최종 실제 라우팅은 별도 셀에서 기존 22문항의 전체 지표를 한 번 계산한다. 선택 적용 경로가 없으면 기존 BASE 결과를 재사용한다. 최종 3회 반복은 수행하지 않는다.
- 각 기법 완료 후 지표별 평균·평가 문항 수·유형별 결과 및 BASE 대비 비교표를 표시한다. 상세 데이터는 메모리에서 관리하고 핵심 비교표·적용 방향은 마크다운으로 요약한다. 평가 결과 JSON/CSV는 생성하지 않는다.
- 기존/신규 결과를 별도 집계하고 통합 평균만으로 판단하지 않는다. 지연·비용은 비교용이며 단회 소규모 평가로 운영 성능을 확정하지 않는다.

현재 기본 실행 범위는 **BASE 평가 셀 하나(기존 22문항·6개 지표)**다. 내부 `evaluate()`는 일반 4지표·인용 형식·업무 안전성으로 총 3회이며, 내부 심사 API 호출은 더 많다. 후보는 해당 기법을 명시적으로 선택해 그 기법의 셀을 실행할 때만 추가 평가한다.

## 5. 진단 및 직접 선정 프로세스

`final_gate`는 진단 전용으로 사용하며 자동 통과·탈락이나 허용 하락폭을 적용하지 않는다. BASE와 후보의 모든 메트릭 평균·차이·하락 항목을 표시하고, 평균에서 상쇄된 문항별 하락도 확인한다. 위험 수준 상승 문항, 위험 수준 2 이상·3 문항 수의 변화와 판정 이유를 함께 보여준다. 수치 비교의 1e-9는 부동소수점 오차 처리값이며 품질 허용폭이 아니다.

1. **평가 유효성 확인**: 동일 문항 ID·평가 범위·유효 평가값을 확인한다. 대상 제외 NaN과 실행 오류를 구분한다.
2. **메트릭 변화 진단**: 충실도·관련성·정밀도·재현율·인용 형식·업무 안전성의 BASE 대비 차이와 하락 항목을 모두 표시한다. 개선이 특정 하락을 자동 상쇄하지 않으며 자동 탈락도 하지 않는다.
3. **문항별 직접 검토**: 하락 또는 업무 위험 상승 문항의 참조 정답·실제 BASE/후보 답변·검색 근거·저장된 업무 위험 사유를 확인한다. 일반 RAGAS의 원래 심사 사유는 저장되어 있지 않으므로 점수만으로 원인을 확정하지 않는다. 필요할 때만 별도 추가 심사 진단을 수행한다.
4. **신규 검증 대상 직접 선정**: `FINAL_MANUAL_CANDIDATES`에 유형별 후보 목록과 각 선택 이유를 기록한다. 현재 검증 대상은 조건 P1·R1과 부정/예외 S1이며, 동일 유형의 후보는 확정 신규 5문항과 BASE 결과를 공유한다. 빈 설정은 미선정이다. 작성한 후보만 신규 5문항 검증 대상으로 사용한다.
5. **신규 검증 후 적용 직접 결정**: `FINAL_MANUAL_VALIDATION`에 유형별 approve(True/False)와 문항 확인 이유를 기록한다. 모든 선정 후보의 신규 진단을 확인한 뒤 승인할 candidate 하나를 명시하며, 미승인 유형은 BASE를 유지한다. 미지정은 결정 대기이며 모든 대상의 판단을 기록하기 전 최종 라우팅 평가를 시작하지 않는다.
6. **경제성 및 최종 전체 확인**: 직접 승인한 경로로 실제 라우팅을 기존 22문항 전체에서 단회 평가하고 BASE 대비 진단을 확인한다. `FINAL_MANUAL_FINAL`에 정책 채택 여부와 이유를 기록해 최종 확정한다. None은 결정 대기이며 False는 BASE 유지다. 3회 반복은 수행하지 않는다.

새로운 중대한 업무 오류와 필수 조건 누락은 반드시 원문을 검토하고 적용 판단 이유에 기록한다. 소규모 평균 차이는 자동 허용폭으로 판단하지 않으며 최종 판단 책임과 근거를 명확히 남긴다. 기존셋과 신규셋 결과는 별도로 확인하고, 추가 검증은 작은 표본에서의 확인으로 표시한다.

## 6. 산출물과 완료 조건

후속 구현·평가 작업은 `mini_project_final.ipynb` 안에서 수행한다. 이번 수정은 계획서만 대상으로 하며 평가 실행·추가 골든셋 생성·앱 적용은 수행하지 않는다.

- BASE 전체 지표 평가 셀 → 각 후보 기법의 전체 지표 평가 셀 → 명시적 유형별 후보 비교 → 신규 검증 → 실제 라우팅 단회 평가 → 최종 선택의 각 로직 앞에 간단한 흐름 설명 마크다운 셀을 추가한다.
- 선택 적용 검증 대상 유형에만 신규 골든셋 5문항씩을 별도 JSON으로 저장하고, 파일 경로·개수·단계별 검수 요약을 마크다운 셀에 정리한다.
- 각 평가 로직 뒤에 기존 Retrieval 적용범위 분석과 유사한 **평가 조건 요약 + 비교표 + 적용 방향 2~3개** 형식의 마크다운 셀을 작성한다. 전체 본문·모든 심사 사유를 나열하지 않고 핵심 실패 사례만 남긴다.
- 선정된 유형의 신규 골든셋 JSON만 데이터 파일로 저장하고, 평가 결과 JSON/CSV나 별도 결과 보고서는 생성하지 않는다. 상세 실행 데이터는 노트북 메모리에서 처리하고 최종 핵심 결과와 재실행 가능한 로직은 노트북에 남긴다.

## 7. 확정된 작업 조건

1. 질문 유형별 선택 적용을 허용하며 실제 라우터를 포함한 정책을 평가한다.
2. 비용·지연·평가 예산에 별도 한도를 두지 않고 품질과 비용의 비교 결과를 제시한다.
3. BASE 대비 진단과 문항 확인 후 신규 검증할 후보를 직접 지정한 경우에만 해당 유형의 신규 5문항을 선정해 별도 JSON에 저장한다. 기본 검색 유지 유형에는 추가 생성하지 않으며 총량은 선정 유형 수에 따라 결정한다. 답변가능 유형은 1차 인용정합성 → 1.5차 정답실질성 → 2차 자기완결성 검수를 적용하며 무답변은 답의 부재 검증으로 대체한다. 기존 동일 유형 문항은 평가 시 불러오고 기존/신규 결과를 구분한다.

4. BASE 기준선 단계에서는 나머지 후보를 수행하지 않는다. BASE와 각 후보 기법은 별도 셀로 분리하고 기법별 결과를 확인한다. 각 기법의 일반 4지표와 커스텀 2지표는 해당 기법의 셀 안에서 모두 계산한다. 최종 3회 반복은 제거한다.

5. `final_gate`는 메트릭 하락·업무 위험 상승 진단만 수행하며, 기존·신규·최종 선정은 문항 확인 후 직접 지정한다.
