# ③ API 선택 규칙

경로의 단계마다 **후보 찾기 → 점수 → 확정 검사 → 고르기** 순서로 API 하나(+ 구분값)를 정한다.
선택 · 가선택 기준은 그래프가 있든 없든 같다. 코드: `src/tap/apis/select.py`, `src/tap/graph/match.py`.

## 1. 후보 범위

- API Catalog 에서 사용 중인 API, 1차 범위 도메인(pd · od · ds)만
- 조회 단계는 조회 API, 쓰기 단계(생성 · 수정 · 상태변경)는 쓰기 API 에서만

## 2. 점수 (0 ~ 1)

이름 비슷함 `sim`: 같으면 1.0 · 한쪽이 다른 쪽을 품으면 약 0.67~0.8 · 글자만 겹치면 최대 0.7 · 반대 낱말(취소 등)이 한쪽에만 있으면 × 0.5

| 단계 | 점수 |
|---|---|
| 그래프 전이 (상태변경) | 요청에 상태 필드가 있으면 도착 상태 코드를 바로 넣는 API 0.85~1.0 (새로 만드는 API 는 0.6). 아니면 업무 이름 ↔ 구분값 이름 · 별칭, 안 맞으면 API 이름 × 0.8 |
| 그래프 조회 (출발 데이터) | 요청에 상태 필드가 있으면 0.9, 아니면 상태 이름 ↔ 구분값 이름 |
| 그래프 없는 생성 | 새로 만드는 API 만. 0.2 + 0.6 × 이름 + 0.4 × 설정값 필드 일치율 |
| 그래프 없는 수정 | 0.6 × 이름 + 0.4 × 설정값 필드 일치율 (새로 만드는 API 는 × 0.5) |
| 그래프 없는 대상 조회 | 0.6 × 찾을 조건 필드 일치율 (최고 0.6) |
| 참조 조회 (이름 → 코드) | 요청에 이름 필드 + 응답에 코드 필드 = 0.75, API 이름이 '○○ 조회'에 가까울수록 1.0 까지 |

그래프 없는 단계의 이름 비교는 흔한 말(상품 · 요청)을 빼고 동작 낱말을 대표어로 맞춘다 (변경 · 바꾸기 → 수정, 생성 · 추가 → 등록).
필드 비교는 한글명이 같은 뿌리로 끝나는지 본다 (가격 ↔ 매입가격). 코드 · 이름은 섞지 않는다 (협력사코드 ≠ 협력사명).

## 3. 확정 검사

| 결과 | 조건 |
|---|---|
| 탈락 | Metadata 에 없음 · 조회/쓰기 종류가 반대 · 사용 안 함 · 구분값 필드가 요청에 없음 · 구분값이 `?`(목록 미완성) · 완성된 구분값 목록에 없는 값 |
| 주의 | 구분값이 Metadata 에 없음 · 일부만 정리된 목록에 없는 값 · API 에 구분값이 있는데 값을 정하지 않음 · 되돌릴 수 없는 API |
| 통과 | 그 밖 |

`rowType` · `rowFlag` 는 구분값이 아니라 행 상태값이라 검사에서 뺀다 (업무 동작으로 채운다).

## 4. 고르기

```
탈락 · 0.45 미만 제외 ── 남은 후보 없음 ──→ 보류   (그래프 없는 단계는 0.3~0.45 후보를 LLM 에)
        │
        ├─ 후보 1개 또는 1위 - 2위 ≥ 0.15 ─→ 규칙이 고름
        │     선택:  점수 ≥ 0.75 그리고 통과
        │     가선택: 그 밖
        │
        └─ 비슷한 후보 여럿 ──────────────→ LLM 이 후보 안에서 고름 (맞는 게 없으면 보류)
              가선택: LLM 우려 · 주의 · 0.45 미만에서 고름 · 점수 0.75 미만 중 하나라도
              선택:  그 밖
```

가선택 · LLM 이 고른 단계는 등록 때 사람이 그 단계를 직접 확인해야 승인된다 ([architecture.md](architecture.md) 승인 게이트).

## 5. 기준값과 근거

| 값 | 뜻 |
|---|---|
| 0.75 (`FOUND`) | 선택 — "이름이 사실상 같다" |
| 0.45 (`CHECK`) | 후보로 인정 — 반대 동작(배송완료취소 ↔ 배송완료 = 0.36)을 거른다 |
| 0.3 (`LOW`) | 그래프 없는 단계에서 LLM 에 물어볼 최저 점수 |
| 0.15 (`MARGIN`) | 1 · 2위 차이가 이만큼이면 규칙이 고른다 |

1주차에 이름 비슷함 점수 구조에 맞춰 정한 경험값이다. 2026-11-12 정답셋(주문 그래프 정답 14건 + 단계 정답셋 S01~S08)으로 점수 분포를 확인했다.

| 단계 | 정답 점수 | 오답 후보 최고 |
|---|---|---|
| 그래프 전이 · 조회 | 0.8 ~ 1.0 | 0.31 ~ 0.67, 출고취소만 0.80 |
| 그래프 없는 생성 · 수정 · 참조 조회 | 0.8 ~ 1.0 | 0.34 또는 없음 |
| 그래프 없는 대상 조회 (S07 · S08) | 0.3 ~ 0.6 | 정답과 같은 점수 (동점) |

- 0.45 ~ 0.75 구간에는 정답이 없었다 — 이 구간 1순위를 가선택으로 두는 규칙과 맞다.
- 오답이 0.75 를 넘은 경우(출고취소 0.80)는 1 · 2위 차이(0.2)가 막았다.
- 정답 최저가 0.8 이라 기준을 올릴 근거는 없다.
- 그래프 없는 대상 조회는 점수 상한이 0.6 이라 늘 LLM 이 고르고 가선택이 된다 — 조회 응답이 다음 쓰기에 넘길 값을 주는지를 점수에 넣는 개선안이 있다 (보류).
- 표본이 작고(주문 출고 API 에 몰림) 그래프 이름과 구분값 이름이 같은 낱말이라 1.0 이 나오기 쉽다. 내부 명세로 정답셋을 늘리면 다시 본다.
