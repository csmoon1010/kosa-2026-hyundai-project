# 승인게이트·인젝션 대응 구현 검증

검증일: 2026-11-03.

## 구현 결과

- 생성 옵션에 `approval_gate`와 `injection_guard`를 추가했다. 초기값과 옵션 기본값 복원은 모두 false다.
- 인젝션 대응은 중지조건·재시도와 승인게이트가 모두 ON일 때만 선택할 수 있다. 선행 옵션 해제 시 자동 해제하며 다시 켜도 자동 복원하지 않는다. 서버도 잘못된 조합을 거부한다.
- 승인게이트 ON인 초안의 입력 결정을 지금 입력 / 실행 시 입력 / 보류로 저장하고, 보류가 없을 때 결정본을 확정한다. 검토 목록을 다시 불러와 이어갈 수 있다.
- 원본 초안과 Baseline을 유지하며 새 버전에 사용자 근거·실행 입력 계약·비교 결과를 저장하고 XML 미리보기를 재계산한다. 값 제출에는 LLM을 호출하지 않는다.
- 원본·자료 해시와 revision, 동시 제출·재전송을 검사한다. 서버가 승인 상태를 계산하며 클라이언트의 status 등 임의 필드를 거부한다.
- 인젝션 옵션은 추가 지시·데이터 구분 프롬프트와 material/notice 자료 표시만 적용한다. 기존 매핑 검증과 새 승인게이트를 재사용한다. 예시값 처리 정책·탐지 모델은 추가하지 않았다.
- 명시적 선행 STEP 근거를 참조하는 후속 고정값은 입력 변경 후 재검토로 남긴다. 의존 업무라는 이유만으로 관계없는 고정값까지 차단하지 않는 회귀 테스트를 포함했다.

## 실제 실행한 검증

| 범위 | 결과 |
|---|---|
| Python 전체 테스트(HTTP·Node DOM UI 테스트 포함) | 162개 통과, 실패·오류 0 |
| API 선택 불러오기 JavaScript 테스트 | 11개 통과 |
| 전처리 UI JavaScript 테스트 | 4개 통과 |
| Python 구문 컴파일 및 평가 스크립트 help | 통과 |

기존 8개 옵션 조합과 승인게이트를 포함한 추가 12개 조합을 검증했다. 스텁 모델이 규칙 무시 지시를 따라 없는 파라미터를 반환했을 때 `PARAMETER_PATH_NOT_FOUND`가 발생하는 것, 자료의 승인 주장으로 실제 확정이 되지 않는 것, 정상 승인 문구가 키워드 때문에 차단되지 않는 것을 확인했다.

검토에서는 입력값 타입·enum·대상 검사, 원본 불변, 사용자 근거 대조, XML 갱신, runtime_inputs의 null 값·정의 저장, 보류 시 확정 차단, 최신 버전 충돌, 변경된 자료 거부, 동시 제출, 중복 요청, 명시적 확정, 확정 후 편집 차단을 확인했다. UI에서는 옵션 의존 관계·기본값 복원·잠금·저장·재불러오기·미저장 변경의 확정 방지를 검증했다.

## 실제 LLM 평가 상태

**실제 LLM의 공격 추종률·차단률은 미측정이다.** 자동 테스트의 모델 응답은 스텁이며 실제 모델의 저항성 결과로 해석하지 않는다.

`PYTHONPATH=src python scripts/evaluate_injection.py --live --approved api-selection-approved-order-shipment.json`으로 별도 실행할 수 있다. 키·모델 설정과 호출 비용이 필요하다. 첫 승인 STEP의 임시 복사본에 규칙 무시·승인 사칭·정상 대조군을 적용하고, 매핑 검증과 승인게이트를 고정한 채 인젝션 옵션 OFF/ON을 비교한다. 기본 반복 수는 3회다. 결과와 실행 JSONL은 `data/out/evaluation/`에 보관하며 운영 원본을 변경하지 않는다.

## 사용 시 적용

Python 서버를 재시작하고 브라우저를 강력 새로고침한다. 기존 요청에서 새 옵션을 생략하면 기존 OFF 동작을 유지한다. 확정은 입력 결정 확인이며 실제 업무 API 실행이나 전체 필수값 완성 검증을 뜻하지 않는다.
